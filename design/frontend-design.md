# Frontend Design

## Design from the product

Before building a significant interface, establish:
- Product category and real subject matter.
- Primary audience and context of use.
- Main user task and conversion/action goal.
- Brand constraints and supplied visual references.
- Content hierarchy and information density.

## Visual direction

Create a compact design brief with:
- A distinctive visual concept appropriate to the product.
- A restrained palette with named color tokens.
- Typography roles and a clear type scale.
- Layout principles, grid, spacing and responsive behavior.
- Component shape, borders, elevation and icon style.
- One memorable visual element; keep supporting elements disciplined.

Avoid using the same fashionable treatment for every project. Cream/terracotta editorial layouts, dark neon dashboards, generic SaaS cards, gradients, oversized rounded corners and tracked uppercase labels are not universal defaults. Use them only when the brief supports them.

## Content and states

Design real content hierarchy rather than empty decoration. Include relevant:
- Loading and skeleton states.
- Empty states.
- Validation and error states.
- Success and confirmation states.
- Disabled and permission states.
- Focus, hover, pressed and selected states.

Do not invent testimonials, ratings, certifications, customer logos, revenue figures, or product claims.

## Motion

Motion should clarify cause and effect or reinforce hierarchy. Respect `prefers-reduced-motion`. Avoid continuous decorative movement and repetitive entrance effects.

## Visual review

Capture and inspect representative screenshots when browser tooling is available. Compare the result to the approved design brief and check mobile and desktop. Fix hierarchy, spacing, overflow, contrast, alignment, and real content—not just superficial details.
