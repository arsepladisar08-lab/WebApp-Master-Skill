# Workflow: Existing WebApp

1. Inspect Git status; preserve uncommitted user work.
2. Read project instructions, README, package manifests, lockfiles and relevant docs.
3. Map the requested flow and the files/data it touches.
4. Identify current stack and conventions; do not replace them casually.
5. State a short implementation plan and risks for non-trivial changes.
6. Make focused changes with regression coverage.
7. Run the most relevant checks and inspect browser behavior when applicable.
8. Review the final diff for unintended changes.
9. Report changed files, evidence, and unresolved items.

Do not rebuild an existing application from scratch merely because a new scaffold is faster.
